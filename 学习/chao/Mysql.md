## 索引结构

B+树：

优点：多路平衡搜索树

1. 多路：树的高度低，IO次数少，访问速度快，通常 3~4 层即可支撑千万级数据，查询时间复杂度O(log n)
2. 平衡：所有数据都存储在**叶子节点**，非叶子节点只存储**索引键（不存数据）**
3. 搜索树：叶子节点之间通过**链表连接**：更好的支持范围查询和排序
4. 树本身：发生页分裂代价低（只用分裂当前页，再更新父节点的索引）





## 索引选择

1. 高频查的数据，尽量控制索引个数，维护索引的成本也不小的
2. 选择性低的数据不适合单独建索引，如STATUS
3. 大key不适合：key越大，数据页存的数据就越少，B+树的层级就越高
4. **主键用自增整型**：避免页分裂，B+ 树插入效率更高
5. 覆盖索引：
   1. **区分度高的字段放前面**
   2. 范围查询字段放最后**（范围后的字段索引失效）**

## 页分裂

**概念：**

Mysql 的数据底层是一个B+树的结构，数据存放在固定大小的页（默认 16KB）中。当插入数据时，某个数据页的空间不足，就会触发页分裂：系统会申请新页，把原页一部分有序数据迁移过去，并调整父节点索引，让B+树重新保持有序

它的本质是“为了维持B+树的有序结构而做的局部拆分”



**什么时候发生：**

当前数据页容量不足，比如，索引不连续会频繁页分裂；正常插入数据时也会发生页分裂



**影响：**

1. 写入性能下降：伴随着数据的迁移和B+树的调整（尤其是聚集索引影响更大）
2. 索引结构变得松散：使每个页的数据不够紧凑



**如何避免：**

1. **主键做递增或趋势递增**（主键的页分裂带来的）
2. 避免使用随机性字段做索引
3. 可能选作索引的业务id最好做趋势递增处理
4. 表设计时避免使用过多的索引
